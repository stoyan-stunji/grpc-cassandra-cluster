!!! da e more simulated pone da se vizda razlika mejdu / & /slow Simulating a Slowdown (Throttling) - Modify a Service A to include an artificial delay (e.g., time.sleep(3)) to simulate high latency/load. Check docker stats to see CPU spikes on the single Service A instance

Manual Scaling and Dynamic Nginx Reload - Start a second instance of Service A manually using a new name and a linked network (e.g., docker run --net=app_default --name servera_2 servera_image). STEP 2: Nginx Update:  manually edit nginx.conf to add server servera_2:8000; to the upstream block. STEP 3: Zero-Downtime Reload: Use (docker exec -it nginx_container_id nginx -s) reload to apply the change without restarting the Nginx container. Prove the load is now distributed by hitting the API and seeing alternating responses (if service returns hostname/ID).
