Proxy / Reverse-Proxy - NGINX
Container Inspection & Logs - docker exec -it <container> /bin/bash, docker exec -it <container> bash, docker exec -it <container> ash, docker logs -f <container>, and docker inspect <container>
Nginx Reverse Proxy Routing - Trailing Slashes: there is a critical difference in Nginx between location /api/v1 and location /api/v1/. One forwards the path, the other strips it, leading to 404s on the backend.
Simulating a Slowdown (Throttling) - Modify a Service A to include an artificial delay (e.g., time.sleep(3)) to simulate high latency/load. Check docker stats to see CPU spikes on the single Service A instance
Manual Scaling and Dynamic Nginx Reload - Start a second instance of Service A manually using a new name and a linked network (e.g., docker run --net=app_default --name servera_2 servera_image). STEP 2: Nginx Update:  manually edit nginx.conf to add server servera_2:8000; to the upstream block. STEP 3: Zero-Downtime Reload: Use (docker exec -it nginx_container_id nginx -s) reload to apply the change without restarting the Nginx container. Prove the load is now distributed by hitting the API and seeing alternating responses (if service returns hostname/ID).
Container Resource Limits - Add deploy: resources: limits: {cpus: '0.1', memory: '100M'} to one of the Python services in docker-compose.yml. Use docker stats while hitting the throttling endpoint.
